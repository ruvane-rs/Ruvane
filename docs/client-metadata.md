# Client page metadata

Alpha.39 carries a complete typed metadata replacement with a client page. SSR,
initial hydration, navigation, cache hits and history use the same values. No
third-party dependency or additional runtime asset is required.

```rust
use ruvane::{ActionData, App, ClientPageData, Metadata, Robots, SiteOrigin};
let mut app = App::new();
app.client_metadata_origin(Some(SiteOrigin::parse("https://example.com").unwrap()));
let metadata = Metadata::new().description("Read the latest updates.").unwrap()
    .robots(Robots::IndexFollow);
let page = ClientPageData::new("Updates", ActionData::default()).metadata(metadata);
```

Configure the same trusted canonical origin in the shared App declaration used
by native and Wasm. `PageContext::origin` and `PageContext::metadata` fall back to
this explicit setting when the router supplies no public origin. The framework
does not derive the canonical origin from Host or forwarded headers. A canonical
URL outside the configured origin, or any canonical without a configured origin,
is rejected before mounting. Canonical paths may intentionally differ from the
request URL. Descriptions and robots policies do not require an origin.

The file starter supplies page descriptions through its existing loaders and
`pages::metadata` helper. Edit its shared `application()` to configure a public
canonical origin. Existing projects are not rewritten.

## Complete replacement

Supported slots are title, description, robots, canonical URL and internal PNG
favicon. Unspecified fields are cleared, not inherited from the previous route.
An explicit `Metadata::new()` clears the optional slots. Fields remain bounded,
escaped text and typed URLs; no arbitrary metadata names, HTML, script, style or
http-equiv attributes are accepted. Existing Metadata setters replace one slot.

`ClientPageData` without metadata preserves legacy packet encoding. Once managed
metadata has been activated, a successful legacy packet clears the supported
optional slots. Legacy packets remain readable. Error packets generated by App
carry an explicit safe replacement: no canonical, noindex, and no stale page
description. Sanitizing a supplied error metadata value preserves its nofollow
policy. Plain transport failures keep the displayed page and its head unchanged.

The navigator prepares detached, bounded head nodes only after the complete
response and application schema validate. It rechecks the existing managed nodes
and commits with the displayed branch. Prefetches, loading prefixes, cancelled
responses, timeouts and rejected packets do not update the head. Cache entries
store the complete packet, so back/forward and cached navigation restore the
same metadata. Error responses remain uncached.

The managed slots are deduplicated. Charset, viewport, CSP, scripts, stylesheets
and unrelated metadata are retained. PNG icons use internal URLs; other icon
types remain outside this typed slot. Metadata is public page information, not
an authorization mechanism. Cookie/authorization cache restrictions still apply.

## Streaming and hydration

Progressive navigation prefixes carry no metadata. Only a fully validated final
packet updates the head; interrupted or superseded streams retain the previous
page's values.

For an initial streamed document, `ClientDocument::metadata` must match an
explicit metadata replacement returned by the leaf loader. The title must also
match, as before. The prepared head is sent once, then the matching metadata is
included in the final embedded snapshot. A mismatch becomes a typed error and
its final snapshot removes canonical indexing hints in the browser. Already sent
HTTP headers and head bytes cannot be rewritten: late stream errors retain the
existing transport contract. Native mode is buffered. Custom 404 profiles also
keep their existing buffered initial-document behavior.

Initial hydration uses its embedded snapshot without another page GET. The
browser validates metadata with the same Wasm App before changing owned head
slots. Streaming head declarations with a configured canonical origin are checked
before headers, including the metadata byte budget.

## Wire and budgets

RVP5 wraps one RVP1/RVP2/RVP3 packet: marker, inner length u32, exact inner packet,
then a metadata presence byte and its supported fields. Nested RVP5 frames and
metadata on pending RVP4 prefixes are rejected. Description/canonical/favicon
strings have u32 byte lengths; robots use a fixed enum code. Unknown flags,
invalid UTF-8, malformed URLs, unsafe error policies and trailing bytes fail.
The RVI1 snapshot and RVS1 stream envelopes remain unchanged.

Metadata is at most 8 KiB and remains inside the existing 64 KiB complete packet
budget. Descriptions are at most 1024 UTF-8 bytes. Canonicals retain the bounded
SiteOrigin plus InternalUrl profile; icons retain InternalUrl limits. Native and
Wasm decoders enforce the same structure. The JavaScript decoder performs its
own bounded preflight, followed by the authoritative Wasm origin/schema checks.
The navigator manages at most 32 existing head nodes and five replacements.

ABI v12, 22 Wasm exports, four runtime assets and two first-party workspace
packages remain. Tests use Rust, Node and the browser without external libraries.
